## Lyriscope for Spotify 1.0.5

1.0.2 → 1.0.5 都是在修"歌词明明是好的，用起来却不对"这一类问题。安装方式没变：装 APK → LSPosed 里勾选 Spotify → 强制停止 Spotify 再打开。

### 修了什么

**手动选的字幕会自己变回去（1.0.2 / 1.0.4）**

以前只有 LRCLIB 那条手动路径会把结果写进缓存；从网易云、QQ、酷狗选中的结果只更新了界面，没落盘，也没打"这是读者自己选的"标记。于是离开播放页再回来，读到的是上一次自动匹配的结果——你选的日文歌词变回了英文。

现在手动结果会写进内存与磁盘缓存，并带上 `manual` 选择标记：自动重校验不会再动它，切歌回来也还在。应用手动结果时还会取消在途的旧请求，避免它在后面把新结果盖掉。

**纯文本歌词让整张卡片变成"聋子"（1.0.3）**

LRCLIB 有些条目只有文字、没有时间轴（`synced=false / plain=true`）。命中区域原本只为"有时间轴的行"建立，于是一份纯文本歌词没有任何命中区：长按不响应、点击无处可跳、视觉上像卡住。

现在纯文本行也有命中区：**长按照常打开面板**，点击跳转只在有时间戳时生效。应用纯文本歌词时状态栏会明确写："这份歌词没有时间轴：不会跟随播放，点击某句也无法跳转。"

**启动即崩（1.0.2 / 1.0.5）**

两次都是文案与日志层面的问题：

- 设置首页新增的分组名在部分语言里是空字符串，而 `AppI18n` 把空串当致命错误——它在大卡片第一次挂载时初始化，所以表现为"点迷你播放器就闪退"。现在缺翻译一律回退英文，不再抛异常。
- 我给缓存判断加的诊断日志读了一个可能为 null 的结果字段（缓存未命中是常态），第一张卡片挂载就空指针。已加空值保护。

### 顺带

- 设置首页分成四组：当前歌曲 / 歌词 / 显示与播放 / 应用，底部有可点击的致谢页。
- 四套长期报红的回归脚本修好了（不是产品坏了，是脚本自己过期）：编码、classpath 分隔符、字段抽取、已被移除的界面控件与登录状态。

### 需要知道

- **签名**：仍是调试证书。从 1.0.1 直接覆盖安装即可；如果哪次提示签名冲突，只能卸载重装，模块内的偏好会一起清掉。
- **只发模块包**：独立应用需要自己编译。
- 歌词、译文与视频来自第三方，版权归各自权利人；请自行确认使用范围。
